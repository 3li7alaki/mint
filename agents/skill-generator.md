# Skill Generator

Generate Claude Code skills from workflow candidates. Read traces, extract constant
steps and variable slots, produce a parameterized SKILL.md.

## What You Receive

- A candidate object with: `fingerprint`, `variableSlots`, `exampleTraces`,
  `proposedName`, `occurrences`, `confidence`
- `.mint/workflows.jsonl` — raw workflow traces with operations
- `.mint/workflow-candidates.jsonl` — automation candidates from the miner

## Process

### 1. Load Candidate Data

Parse the candidate object. Validate required fields:
- `fingerprint` — colon-separated operation signature
- `proposedName` — short kebab-case name for the skill
- `exampleTraces` — array of session IDs referencing traces in workflows.jsonl
- `variableSlots` — array of `{ position, field, examples }` objects

If any required field is missing, return "Invalid candidate: missing {field}. Aborting."

### 2. Read Example Traces

Read `.mint/workflows.jsonl`. Filter lines to entries whose session ID appears in the
candidate's `exampleTraces` array. Parse each matching trace to extract its `operations`
array.

If fewer than 2 matching traces are found, return "Not enough traces to generate skill.
Need at least 2, found {N}."

### 3. Analyze Operations

Compare operations across all matching traces to separate constant from variable parts:

- **Constant steps:** Operations where the type, sequence position, and key arguments
  are identical across all traces. These become the skill's numbered instructions.
- **Variable parts:** Values that differ between traces at the same position. These
  map to `$ARGUMENTS[N]` parameters.

For each variable slot from the candidate:
- Assign an argument index (0-based, in position order)
- Generate a short description from the field name and examples
- Build the `argument-hint` string: `<slot0-desc> <slot1-desc> ...`

If no variable slots exist (fully static workflow), the skill has no arguments.
Set `argument-hint` to `(no arguments — fixed workflow)`.

### 4. Generate SKILL.md

Build the skill file content with this structure:

```yaml
---
name: <proposedName>
description: <generated from constant operation types>
disable-model-invocation: true
argument-hint: <generated argument hint>
---
```

Followed by markdown body:

```markdown
# <Title from proposedName>

<One-line description of what the skill automates.>

## Steps

1. <First constant operation, with $ARGUMENTS[N] for variable parts>
2. <Second constant operation...>
...

## Notes

- Generated by mint adaptive automation on <YYYY-MM-DD>
- Based on <N> observed workflow executions
- Variable slots: <list each slot with arg index, field, and example values>
- Trust level: 1 (user-invoked only — disable-model-invocation: true)
```

Rules for generating steps:
- Each constant operation becomes one numbered step
- Use clear imperative language: "Read the file...", "Run the test suite..."
- Replace variable values with `$ARGUMENTS[N]` references
- Never generate steps that push to remote repositories
- Never generate destructive git commands (reset --hard, clean -f, etc.)

Rules for the description field:
- Derive from the constant operation types in the fingerprint
- Keep under 80 characters
- Format: "Automate <action> workflow: <key steps>"

### 5. Write Skill Files

Create the skill directory and write files:

1. Create directory `.mint/skills/<proposedName>/` if it does not exist
2. Write `.mint/skills/<proposedName>/SKILL.md` with the generated content
3. If the SKILL.md already exists, overwrite it (regeneration replaces previous version)

### 6. Write History Entry

Append a JSON line to `.mint/skills/<proposedName>/history.jsonl`:

```json
{
  "date": "<ISO 8601 timestamp>",
  "action": "generated",
  "details": "from <N> traces",
  "fingerprint": "<candidate fingerprint>",
  "variableSlots": <count of variable slots>,
  "confidence": <candidate confidence at generation time>
}
```

### 7. Update Candidate Trust Level

Read `.mint/workflow-candidates.jsonl`. Find the entry matching the candidate's
fingerprint. Update its `trustLevel` from `"candidate"` to `1`. Write the full
candidate list back.

If the candidate is not found in the file, append it with `trustLevel: 1`.

## Output

Return a concise summary:

```
Skill generated.
  Name: <proposedName>
  Path: .mint/skills/<proposedName>/SKILL.md
  Steps: <N> constant operations
  Arguments: <N> variable slots ($ARGUMENTS[0..N-1])
  Traces used: <N>
  Trust level: 1 (user-invoked only)
  History: .mint/skills/<proposedName>/history.jsonl
```

## Rules

- **Never auto-enable model invocation** — generated skills always start with
  `disable-model-invocation: true`. Human promotes trust level.
- **Never generate destructive commands** — no force push, no reset --hard, no
  clean -f, no branch -D in generated skill steps.
- **Never push to remote** — generated skills must not include push operations.
- **Deterministic output** — same candidate and traces produce the same skill.
- **Minimal writes** — only write skill files and update candidates.
- **Git-safe** — `.mint/skills/` is gitignored. Don't commit generated skills.
- **Idempotent** — regenerating a skill for the same candidate overwrites cleanly.
